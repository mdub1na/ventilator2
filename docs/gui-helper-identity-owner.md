# Один сеанс проверки новой identity Ventilator

Фоновая активность старой копии уже включена, но macOS продолжает считать административный допуск незавершённым. Этот сеанс проверяет гипотезу о сохранённой истории старых идентификаторов через новую пару `dev.ventilator.app` / `dev.ventilator.app.helper`. Успех не обещан. Обычное системное разрешение по-прежнему обязательно; сертификат и проверки root XPC сохранены.

Профиль **Mac15,7 / macOS 27.0.1 / 26A434 остаётся read-only**. Полный хронологический список аппаратных записей: **`[]`**, число записей **0**. Сеанс не содержит аппаратного review, approval, старта worker или опыта возврата Auto. Старая регистрация и её файлы не удаляются глобальным сбросом.

## Полный порядок владельца — примерно 3–7 минут

Выполните **один раз** в обычном Terminal, без внешнего sudo:

```bash
python3 /Users/mdub1na/IdeaProjects/ventilator2/.build/gui-helper-identity-owner/session.py run
```

Один скрипт проведёт весь сеанс:

1. **Выход → CLOSED.** Завершите установленный Ventilator через меню «Выйти» или Command-Q. Закрытие окна оставляет приложение работающим. Введите CLOSED после выхода; скрипт сам проверит отсутствие процесса, без принудительного завершения.
2. **Подпись → проверка → пароль Terminal.** Подтвердите доступ к Apple Development ключу в системном окне Keychain, если оно появится. Отсутствие запроса нормально при уже разрешённом доступе. Скрипт подпишет только новую payload, проверит сертификат/positive revocation и напечатает хеши app/helper/plist до снятия старой регистрации. Пароль sudo вводите только в своём Terminal при запросе. Он нужен для root staging, ограниченных чтений launchd, точного backup и замены. Он не заменяет системное разрешение помощника.
3. **Автоматическая проверка и замена.** Новая служба должна отсутствовать; старая должна быть pending либо уже снята с регистрации. Любой enabled/unknown ответ, существующий root job или root runtime запрещает снятие регистрации и замену. Для pending старый exact binary выполняет один штатный guarded unregister. Повторный absent job обязателен. Exact старая копия сохраняется в `previous-installed.bundle` этого пакета; новую root-owned копию скрипт устанавливает в `/Applications/Ventilator.app`. На этом этапе менять фоновую активность не нужно.
4. **Подключение → CONNECTED → ON → ALLOW/NONE.** В новом окне нажмите **«Подключить помощник» один раз**, если кнопка включена, затем введите CONNECTED. Откройте «Системные настройки → Основные → Объекты входа и расширения → Фоновая активность приложений». Проверьте, что новая запись Ventilator включена; если выключена, включите, затем введите ON. Уже включённую оставьте включённой. Если появится уведомление Background Items Added, выберите Allow и подтвердите пароль/Touch ID администратора. Введите ALLOW только после настоящего подтверждения; NONE — если запроса не было. Если кнопка недоступна, новой записи нет или действие невозможно, введите CANCEL. Не включайте старую backup/retired запись. Если записи невозможно различить, остановитесь с CANCEL.
5. **Результат → прислать последние строки.** Скрипт один раз проверит native status и новую root job. Готовность требует actual enabled, проверенного root XPC с exact новой подписью и loaded job. Только при этом он дополнительно проверит unsupportedMachine без аппаратного опыта. Pending/failed результат тоже сохраняется и завершает сеанс. При любом STOP пришлите последние строки; команды run/register/ready и старые сеансы не повторяйте.

Сон и перезагрузка не нужны. При STOP подписанная payload, маркеры, staging/backup и текущая установленная копия остаются в достигнутом состоянии. Автоматического отката или повтора нет. До замены старая копия остаётся в /Applications; после замены её exact bytes находятся в backup нового пакета. Не перемещайте файлы и не меняйте разрешения повторно до анализа результата.

## Что связано и проверяется

Manifest связывает owner, текущий boot, machine, fixed old/new identities, certificate/Team, script/PLAN hash, новую payload, пять прежних installed файлов, два private GUI marker и **14 protected директорий**. Frozen пакеты и старая подпись сохраняются побайтно. Signed seal создаётся владельцем после positive qualification до lifecycle. Полный подготовительный hash находится в manifest; скрипт выводит весь PLAN до действий.

Новый plist basename, Label, MachServices и helper signing identifier совпадают. Новый inspector не принимает прежние identities или лишний legacy plist. Требования Apple anchor, Team, CDHash, canonical path, root ownership, loaded peer PID/UID/nonce/expiry остаются обязательными. Staging проверяется только статически, без ServiceManagement. Ограниченные launchd reads относятся только к двум фиксированным labels; global resetbtm, ручной bootstrap/bootout/kickstart, private-key ACL changes отсутствуют.

После run-started повтор запрещён. GUI регистрирует только новую службу и сохраняет единственную durable попытку. CONNECTED/ON — сообщения владельца, а не доказательство системного Allow; actual native/XPC/job результат записывается отдельно. Прежний probe и модели не заменяют эту проверку на оборудовании.
