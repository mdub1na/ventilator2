Переключатель сейчас on. Следующий шаг — один ограниченный цикл переключателя для уже зарегистрированной текущей копии. Его успех на macOS 27 не доказан; результат проверим сразу. ## Все действия в порядке выполнения

Продолжительность: 2–3 минуты. Работу сохраните; сон и перезагрузка не нужны. Приложение оставьте в текущем состоянии. Используйте только запись **Ventilator** и `/Applications/Ventilator.app`; другие службы не менять.

1. В обычном Terminal запустите одну команду **без sudo перед python3**:

```sh
python3 /Users/mdub1na/IdeaProjects/ventilator2/.build/helper-registration-approval/snapshot.py collect
```

Wrapper проверит frozen script/plan, 15 owner файлов, три installed hashes, предыдущий административный снимок и owner UID. До предложения переключить службу требуется отсутствие всего runtime root и job. Existing/unknown state → STOP до действия. Перед предложением сохраняется one-shot marker; повтор команды запрещён.

2. Когда Terminal попросит выполнить цикл, откройте **Системные настройки → Основные → Объекты входа → Активность фоновых приложений**. Выключите только **Ventilator**, затем включите **один раз**. Подтвердите системный запрос паролем администратора/Touch ID, если он появится. Отсутствие запроса не объявляется успехом: следующий снимок покажет состояние. Если запись не найдена, имя неоднозначно или система отказала — STOP, не вводите DONE и не повторяйте переключение; сообщите вывод/системное сообщение.

3. Вернитесь в тот же Terminal. После завершённого одного цикла введите **DONE** и Enter. Это подтверждение выполненного системного действия; аппаратного approval оно не создаёт.

4. Wrapper прочитает system job и BTM. Введите пароль sudo в этом Terminal, если понадобится. Пароль в чат не передавать. Ввод может потребоваться для обоих чтений при отсутствии sudo cache. Результат сохраняется локально; в отчёт попадают только записи Ventilator.

5. После **Saved read-only snapshot: .../result.json** сообщите «снимок разрешения собран» и остановитесь. Разработчик проверит job/BTM и затем живой signed root peer. Ready/run/APPROVE/START в этом сеансе нет.

## Полный список команд wrapper

Обычная проверка job (до действия, срок 5 с):

```sh
/bin/launchctl print system/dev.ventilator.helper
```

После DONE — ровно два административных чтения:

```sh
/usr/bin/sudo -- /usr/bin/perl -e 'alarm 5; exec "/bin/launchctl", "print", "system/dev.ventilator.helper"; die "exec failed\n";'
/usr/bin/sudo -- /usr/bin/perl -e 'alarm 20; exec "/usr/bin/sfltool", "dumpbtm"; die "exec failed\n";'
```

Perl только выставляет alarm и выполняет exec фиксированной системной утилиты. Таймер переживает exec и ограничивает чтение 5/20 с после аутентификации; kernel/exec timer и реальный non-root зависший BTM dump проверены ранее. App/helper binary wrapper не запускает; register/unregister/bootstrap/kickstart/resetbtm не вызывает. Подписи и установленные файлы сохраняются. macOS может загрузить зарегистрированный helper после включения фоновой службы; его аппаратный start требует отдельного локального bound approval и остаётся закрытым.

## Остановка и восстановление

При STOP, отказе системной аутентификации/sudo, timeout или неожиданном окне остановитесь, сохраните состояние и сообщите сообщение. Цикл/команду не повторяйте. Ctrl+C прерывает ожидание/чтение; marker и частичные файлы сохраняются. Если выключение удалось, а включение отказало, оставьте службу выключенной и сообщите об этом. Никакой аппаратной записи в этом сеансе нет, аппаратное восстановление не запускается. Старые пакеты/журналы не удалять; глобальный reset или ручной запуск job не выполнять.
