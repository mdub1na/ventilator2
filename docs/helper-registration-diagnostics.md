# Сеанс владельца: только диагностика системной регистрации

После `setup` новое уведомление и административное подтверждение не появились. Последующий ordinary-user status сообщает enabled/remoteFailure; system job не найден. Причина неизвестна. Следующий шаг — прочитать system job и текущие BTM records с административными правами. Этот сеанс завершится сохранением отчёта; аппаратный сеанс остаётся остановленным.

## Все действия в порядке выполнения

1. Откройте обычный Terminal. Службы и приложение оставьте в текущем состоянии. Сон и перезагрузка не нужны. Продолжительность: около минуты плюс ввод пароля.
2. Выполните **одну команду без sudo перед python3**:

```sh
python3 /Users/mdub1na/IdeaProjects/ventilator2/.build/helper-registration-diagnostics/snapshot.py collect
```

3. Введите пароль администратора, когда sudo попросит его в Terminal. Ввод не отображается. Команда может попросить пароль для каждого из двух чтений, если sudo не сохранил временную авторизацию. Запросов фоновой активности, Touch ID приложения или Keychain этот код не вызывает.
4. После `Saved read-only snapshot: .../result.json` сообщите «снимок собран». Разработчик прочитает файл локально; весь BTM dump в чат копировать не требуется. Дальнейших команд в этом сеансе нет.

## Точные привилегированные команды

Wrapper проверит хеши скрипта, этого плана, всех 15 файлов сохранённого owner package и трёх установленных файлов. Затем выполнит ровно следующие команды по порядку:

```sh
/usr/bin/sudo -- /usr/bin/perl -e 'alarm 5; exec "/bin/launchctl", "print", "system/dev.ventilator.helper"; die "exec failed\n";'
/usr/bin/sudo -- /usr/bin/perl -e 'alarm 20; exec "/usr/bin/sfltool", "dumpbtm"; die "exec failed\n";'
```

Perl выставляет таймер и сразу заменяет себя системной утилитой. Alarm переживает exec: зависшее чтение завершается через 5/20 секунд после ввода пароля. Нет root shell, исполняемого root Python или произвольных аргументов. Launchctl выполняет только print; sfltool — только dumpbtm. Wrapper не запускает app/helper, не вызывает register/unregister/bootstrap/kickstart/enable/resetbtm и не меняет подписи/установленные файлы/настройки службы.

В отчёт попадают system job Ventilator и записи BTM с точными identifiers `2.dev.ventilator.macos` / `16.dev.ventilator.helper`, включая UID, URL и disposition. Записи других приложений не сохраняются. Ненулевой exit code и неполный dump сохраняются как отказ; отсутствие stdout не считается доказательством отсутствия BTM record.

## Остановка и сохранение

При STOP, отказе sudo, истечении таймера или неожиданном окне остановитесь и сообщите вывод. Команду не повторяйте; `started.json` сохраняет факт попытки. При необходимости Ctrl+C прерывает чтение. Частичный `launchd.json`/`btm.json` остаётся в папке диагностики. Установленные файлы, текущая регистрация и старый sealed пакет сохраняются; аппаратного восстановления этот диагностический код не выполняет.
