## Точная последовательность

1. **Окно A.** В обычном Terminal без внешнего sudo выполните один раз:

   ```bash
   python3 /Users/mdub1na/IdeaProjects/ventilator2/.build/current-hardware-continuation/session.py run
   ```

   Скрипт проверит неизменность подписи, установленных файлов и завершённых пакетов. Пароль администратора, если запрошен, вводите только в Terminal. Fresh root audit должен содержать только тот же старый истёкший challenge, без approval/ledger/outcome. Любое отличие — STOP. Затем импортируется новый полный review, включающий этот PLAN; импорт и пароль sudo не одобряют запись. Сохранённый старый review остаётся в прежнем пакете.
2. **A → новое окно B.** В A появится длинная команда, начинающаяся `sudo /Applications/Ventilator.app/Contents/MacOS/VentilatorHelper --approve-local-hardware`. Скопируйте **всю эту команду** в отдельное окно Terminal B и выполните. Окно A пока оставьте открытым и ничего в нём не вводите.
3. **Одобрение — только в B.** В B прочитайте полный план и десять записей ниже. Если согласны на точный опыт, найдите напечатанную отдельную строку, которая начинается `APPROVE` и содержит **UUID + два длинных хеша**. Скопируйте **всю строку целиком**, включая эти три значения, в **B**, затем Enter. Одно слово `APPROVE` недостаточно. Если не согласны — CANCEL; сеанс остановится. Это единственное явное аппаратное одобрение. Сама команда B не запускает вентиляторы.
4. **Дождитесь успеха в B.** Должно появиться `Approval saved for challenge …`. Если вместо этого ошибка/declined/STOP — прекратите сеанс и сообщите разработчику. В установленной версии после `challenge` напечатан UUID: скопируйте именно его (36 символов с дефисами). OWNER_UUID из первоначальной команды — другое значение, для START не подходит.
5. **Запуск — только в A.** Вернитесь в первое окно A. Напечатайте `START`, затем **один пробел**, вставьте UUID из успешного сообщения B и нажмите Enter. Получится одна строка из двух частей: слово START и UUID. Одного слова `START` недостаточно. До этой строки аппаратный запуск не запрашивается. Для отмены в A введите CANCEL. Receipt одноразовый и действует 300 секунд для этой загрузки, подписанных файлов, точного плана/review и соединения A.
6. **Оставайтесь в A.** Клиент ждёт подтверждённого подъёма к 2500 RPM, затем автоматически запрашивает Auto. Его ожидание после START ограничено 25 секундами. Дождитесь результата; скрипт сохранит root audit в новом `result.json`. Пришлите последние строки A и B и свои наблюдения. Auto read-back ещё не является физической квалификацией; обычные элементы управления остаются отключены.

Lease 10 с, heartbeat 2 с, Fixed observation deadline 5 с, исходный restore deadline 8 с, operation budget 0.5 с, writer quiescence 1 с. Heartbeat не продлевает lease. Preflight повторяет exact model/version/build/signature/boot/hash/receipt, FNum2, exact key types/sizes/ranges, Ftst0, mode3/mode3, actual/target ≤1800, свежесть и nominal pressure; любой отказ блокирует Fixed. Reader независим от writer. Auto evidence — три отдельных mode readings с интервалом ≥1 с; нулевые RPM не заменяются выдуманными значениями.

После durable closure разрешены лишь оставшиеся непопытанные Auto steps в исходном deadline. MaximumOwnerRecoveryRuns=1 не даёт разрешения повторять вручную. Синхронный IOKit не имеет доказанной отмены или гарантированной задержки уже начатого вызова. Неизвестный эффект/неполный Auto сохраняет pending даже при успехе остальных шагов. HardwareControlAvailable и physicalAutoVerified остаются false.

## STOP и физическая остановка

При STOP сохраните вывод и сообщите разработчику. **Не повторяйте** новый или старый run, APPROVE, START, register/ready, Fixed/Auto; не удаляйте root state и не перезапускайте службу. Все завершённые пакеты сохраняются. До корректного START клиент не вызывает аппаратный start; после отправленного start RPC ошибка может означать уже начатый опыт — для этого собирается audit.

После START при recoveryRequired, неизвестном восстановлении, ошибке или отсутствии результата через 25 с прекратите нагрузки. При нагреве, неправильной работе вентиляторов или невозможности подтвердить возврат управления **физически выключите Mac удержанием кнопки питания**, оставьте выключенным и сообщите разработчику. Выключение не доказывает Auto. Broker самостоятельно выполняет только разрешённые оставшиеся Auto steps; дополнительных SMC команд этот сеанс не предоставляет.

Manifest связывает owner/current boot/machine, installed5/private GUI4, этот PLAN/script/full review, десять writes и 16 protected директорий, включая завершённый предыдущий сеанс. Native улучшенные подсказки подготовлены для будущей сборки; этот сеанс использует прежние signed binaries и уточняет их ввод полным PLAN. Служба и подпись повторно не меняются.
